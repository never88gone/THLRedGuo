> 应用版本固定为 `1.0.0`（Flutter 构建号 `262901343`、tvOS 构建号 `20261017133200` 均保留），唯一官方源为 `1.1.0-dev.6`。播放、真实弹幕、本地收藏和历史已在 tvOS 27、iOS 27 与 Pixel 9a / Android 17 模拟器完成代表性验证，详细结果见文末；登录及官方账号同步继续暂缓。不逐集穷举，也不将抽样结果作为全片库永久可播保证。按用户最新要求，继续在现有 `main` 维护，检查通过后自动提交并推送。

**糖葫芦Haw**（工程标识：`THLRedLook`，包名 / Application ID：`com.never88gone.redlook`）是一款基于 **Flutter + 纯 Dart 高性能核心引擎** 与 **Apple tvOS 原生 SwiftUI** 打造的全平台独立流媒体与短剧聚合应用。

站源请求、协议解析、动态取流、在线播放与离线下载均在设备本地端侧闭环完成，全平台实现真正一键构建与零配置运行；无需搭建任何远程中转或中心化代理服务，兼具极致的启动速度、数据私密性与多端一致的使用体验。

## 核心功能特性

### 🧩 CatPawOpen 标准规范与真实 JS 运行时沙箱
- **开源 CatPawOpen 规范**：预置官方首发免费短剧数据源脚本，采用通用 `spider` 规范（`init`, `home`, `category`, `detail`, `play`, `search`），开箱即用；
- **JavaScript 运行时沙箱**：基于 `flutter_js` 深度封装 `CatPawJsRuntime`，在端侧沙箱内原生执行 JS 脚本，注入完整异步 `fetch` 网络客户端、纯 JS 轻量 DOM 解析引擎以及标准控制台与异常隔离机制；
- **单源上下文与数据闭环**：应用所有功能逻辑均运行于当前激活的数据源上下文，包括分类浏览、搜索联想、剧集详情、排行榜、我的追剧与离线下载；
- **多沙箱端侧并发看护**：基于运行时池与并发队列调度，支持 15s 异步超时熔断与多级优雅降级保底；
- **插件管理与自定义导入**：设置页提供专属【JS 数据源插件管理】控制面板，支持查看已装载插件列表、重新扫描重载，以及通过本地文件、远程链接或剪贴板导入第三方符合 CatPawOpen 规范的 JS Spider 脚本。

### ⚡ 影院级视听与交互
- **自适应清晰度与线路切换**：支持流畅、高清、超清、1080P 及原画平滑切换，支持加密流端侧实时解密与防盗链请求头自动适配；
- **沉浸式手势操作**：
  - 手机竖屏模式：上下滑动快速切集，长按屏幕任意区域触发临时 3 倍速快进，轻点即时启停；
  - 横屏影院模式：左右滑动手势调节进度，上下滑动手势调节亮度与音量；
- **系列多季聚拢与快速切换（Multi-Season Engine）**：智能识别剧集季数信息，详情页与播放器选集列表全景展示多季胶囊，无缝换季起播；
- **画质增强引擎**：Windows 桌面端内置定制化 Shader 增强链路（自动 / 省电 / 清晰优先），显著提升大屏观感；
- **智能预热与秒开连播**：换集前轻量预热下一集连接与直链，实现换集平滑秒开。

### 📥 离线缓存与分集下载
- **分集多选与批量队列**：支持从详情页或播放页直接勾选多集，后台并发调度下载；
- **断点续传与完整校验**：本地高性能下载引擎驱动，网络波动自动重试并支持断点续传；
- **一键更新本剧**：追剧更新时，一键自动扫描并补全缺失或新增的分集；
- **本地零流量播放**：已下载内容完全离线可播，支持导出与本地清理；
- **常亮防息屏**：支持在下载时保持屏幕常亮，防止批量下载中断。

### 🔒 隐私安全与私密空间
- **九宫格手势锁**：支持为应用设置九宫格图形解锁，切至后台自动加锁防窥；
- **后台高斯模糊虚化**：应用切入后台或多任务预览界面时，自动触发高斯模糊遮罩；
- **独立私密短剧库**：专属密码保护的私密空间，私密收藏与专属浏览记录不进入常规历史，全方位守护隐私。

### hongguo-drama 请求逻辑评估（2026-10-17）

按用户提供的 `hongguo-drama` 仓库（`84b6e88` / `1.73.0`）进行了只读检查与实时对照。其 App 签名能调用 `multi_video_model/v1/` 并取得非空模型；这与上述现有单集 Gorgon 路径的空响应结果属于不同实现。参考代码、工具与详细报告只在独立 `thlredguojs` 研究仓库维护，没有引入本项目或发布资源。

抽取同一批 6 部剧的首、中、末集，共 18 集、2 轮 36 次。双方均走本机现有网络，每个媒体探针最多在内存读取 64 KiB，检查有效 MP4 文件头；未请求图片，未保存视频，未做完整解密或解码。当前源通过 12 / 36 次，参考流程通过 17 / 36 次；参考流程仍有 16 次媒体 403、3 次媒体 404，7 个分集两轮结果不同。参考返回的 32 / 36 个模型带内容密钥信息，16 个可读取的 App 文件头带 CENC 加密标记；不能把“有 URL”或“HEAD 200”当作已可播放。

本轮结论为**暂不替换**，官方源仍为 1.0.4，客户端版本不变。参考搜索仍来自官网网页，尚不能补齐 App 独有片库；加密流还需要补齐 CatPaw 密钥传递与 Android 播放适配，并验证 Windows/tvOS 的实际解密。当前网络使用既有 Fake-IP 路由，本轮没有改变代理、VPN 或系统 DNS；结果不代表所有网络或长期可用性。后续可在独立研究仓库复用已验证的签名思路，先解决媒体 403/404 和端侧加密播放，再考虑接入。

### 全部在 THL 内播放的前轮方案研究（2026-10-17）

用户已明确要求播放全过程在 THL 内完成，接口拒绝时也不跳转官方 App。设备端方案为：保留已可用的当前直链，失败时调用完整签名的 App 模型接口，按准确分集选择官方返回的主备地址；刷新模型时同步更新地址、请求头和内容密钥。研究工具最多刷新 5 次，并将 App 回退阶段的网络请求和媒体探针限制在 30 秒预算内，不替换视频主机、不借用其他分集或样片。

相同 18 集、2 轮的组合策略首次取得 34 / 36 个有效 MP4 文件头，仍有 2 次在刷新 5 次后全部 403。补充分集 ID 校验和贯穿请求的超时预算后，另一次完整运行取得 36 / 36 个对应分集文件头，其中 24 个为加密模型。两次运行使用相同恢复策略，结果变化不能归因于超时或校验改动，也不能证明持续稳定或全片库可用。

独立研究工具进一步将 6 部剧各 1 个加密分集完整读取到内存，在本机 FFmpeg 9.0.1 中完成整集视频与可用音轨的解密解码，6 / 6 通过，时长约 58～150 秒；相同文件使用错误密钥时全部解码失败。其中 2 集需要刷新模型 4 次和 2 次才读到完整文件。未请求图片，未将视频、内容密钥或签名 URL 查询参数写入报告或 Git。另有同一部剧首、中、末集各 3 秒的解码验证通过。以上是电脑上的研究证据，尚非 THL 客户端或目标平台的播放验收。

接入顺序如下，优先 Android 和 Windows，全部处理均在设备端完成，不依赖自建远程服务：

1. 在 `thlredguojs` 完成 App 搜索、分页和分集映射；目前搜索仍依赖网站，不能把按已知 ID 取流当作 App 全片库覆盖。
2. 将经过许可审查且保留来源的签名实现适配为客户端 JS 沙箱可运行的实现，消除 Node.js 依赖；通过后仅接入唯一官方源。研究工具仍只在独立仓库维护。
3. 补齐 CatPaw → 播放方案的密钥、主备地址和有效期传递。Android 优先复用已依赖的 FFmpegKit，将 CENC 媒体在本地缓存解密封装后交给现有播放器；Windows 验证现有媒体引擎的解密参数。完整缓存会增加首次等待，需要呈现进度、支持取消并清理不完整文件。
